## Key Design Decisions

### UUID Primary Keys
All tables use `uuid` PKs generated by PostgreSQL's `uuid_generate_v4()`.
- Prevents enumeration attacks
- Safe for distributed inserts
- No auto-increment conflicts across read replicas

### Soft Deletes
All business entities use `deleted_at` soft deletes.
- Branches, Warehouses, Products, Orders, Dealers, Customers, Suppliers

### JSONB Columns
Used for flexible, schema-less data:
- `branches.settings` — branch-specific configuration
- `branches.working_hours` — operating schedule
- `products.dimensions` — {length, width, height}
- `products.meta` — SEO metadata
- `dealers.custom_pricing` — per-product price overrides
- `orders.shipping_address` — address snapshot at order time
- `audit_logs.old_values`, `new_values` — change tracking

### Append-Only Ledger
`stock_movements` is never updated or deleted.
Every stock change creates a new row with `quantity_before` and `quantity_after`.
Current stock is derived from the `stocks` table (cached aggregate).

### Polymorphic References
`stock_movements.reference` → morph to `Order`, `PurchaseOrder`, `TransferRequest`
`payments.payable` → morph to `Order`, `PurchaseOrder`
`audit_logs.auditable` → morph to any model
`notifications.notifiable` → morph to `User`

### Partitioning (Production)
```sql
-- stock_movements partitioned by month
CREATE TABLE stock_movements_2024_01 PARTITION OF stock_movements
  FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');

-- audit_logs partitioned by month
CREATE TABLE audit_logs_2024_01 PARTITION OF audit_logs
  FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');
```
